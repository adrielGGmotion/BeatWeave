# BeatWeave 0.11.0

Explicit transitions can now beat-match songs with different pulse counts per
bar. Compatible bar pairs retain their existing plan. Other pairs align canonical
pulses from the entry downbeats, with a measured half/double-time mapping when
appropriate, while keeping the requested outgoing fade and clock quality limits.

Sparse outgoing acoustic evidence has an explicit bounded inheritance option.
Rejected pulse geometry remains rejected. `transitionCoverage()` lets callers
schedule a blend before the last accepted bar region instead of repeatedly
trying an unsupported outro. See
[rejection meanings and integration](https://github.com/adrielGGmotion/BeatWeave/blob/v0.11.0/docs/transition-rejections.md).

The 0.11.0 model bundle includes current distribution metadata and the same
checksum-verified `small0` and `final0` ONNX weights as 0.10.0. This fixes planner
policy; no retraining or improved detector-accuracy claim is made. The ZIP has an
adjacent SHA-256 checksum. Existing model files remain compatible.

This source release also includes the cue-ranking, pitch-analysis/shifting and
mixer fixes listed in [CHANGELOG.md](https://github.com/adrielGGmotion/BeatWeave/blob/v0.11.0/CHANGELOG.md). Automatic bar searches
retain their complete-bar compatibility policy. Treat this as a development
release; annotated fixture tests establish planning behavior, not the musical
correctness of every real-song analysis.

The original explicit-transition overload remains available. On the new path,
`barMatches` claims entry alignment only, `incomingBars` is null if the fade ends
within an incoming bar, and `transitionAlignment` exposes original indices and
the pulse ratio. Cancellation still throws `MixCancelledException`.

Maven Central's published version remains 0.10.0 until the separate signed 0.11.0
publication is completed. Build 0.11.0 from source or use local publications to
consume these changes. This GitHub source/model release does not publish Central
artifacts. Metrolist is unchanged by this release.
